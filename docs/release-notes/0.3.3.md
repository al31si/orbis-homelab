# Orbis Homelab 0.3.3

The iPhone installed app now reaches the bottom of the screen.

## Fixed

- **Strip below the bottom bar in the iOS 26 installed app.** iOS 26 gives a Home Screen app a viewport one status-bar height shorter than the screen while the page is shorter than the screen. The 0.3.1 fix made the app frame taller, but WebKit does not draw fixed content below that edge, so the strip stayed. In installed apps only (`display-mode: standalone`), the document is now as tall as the screen (`min(100lvh, 100% + safe-area top)`), so iOS expands the viewport itself; browsers and other platforms are unchanged. The JavaScript height correction of 0.3.1 is removed.
- **Phone bottom bar.** The keys now run down to the screen edge: the room for the home indicator is inside the keys (the separators and the current page's key reach the edge) instead of an empty band under them, and it is trimmed to the inset minus 14px, like native tab bars.

## Diagnostics

- **This device** is now the first section of Diagnostics and is shown even while the server diagnostics are loading or unavailable.
- **Safe-area insets** (measured top and bottom, in CSS pixels) replaces **Height correction**. **Viewport** is unchanged. See [Troubleshooting](../troubleshooting.md#bottom-gap-in-the-ios-installed-app).

## Upgrading from 0.3.2

The configuration format and the extension API are unchanged. Follow [Update with Compose](../update.md#update-with-compose) with `VERSION=0.3.3`, then fully close and relaunch the installed app.

## Known limitations

- The `arm64` image is built and inspected but not executed by the project's tests.
- During `0.x` the configuration format and the extension API can change in a minor version; neither changes in this release.
- Extensions run in the backend process with its privileges: install only code you trust.
- One language per instance (`it` or `en`).
