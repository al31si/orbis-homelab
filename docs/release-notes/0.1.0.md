# Orbis Homelab 0.1.0

The first release. Orbis Homelab is a self-hosted control center for a homelab: an installable web app (PWA) served by a small Node.js backend, configured with two YAML files and a `.env`.

## What is in it

- **Pages:** Home, Services, System, Storage, Activity, Settings and Diagnostics, in English or Italian (one language per instance). Every page except Home, Services, Settings and Diagnostics appears only when something feeds it: whatever is not configured does not exist (no page, no request, no alert).
- **Service catalog and checks:** `services.yaml` with HTTP probes, Docker container association, categories, favorites and launch links.
- **Optional data sources:** a system provider ([Glances](../glances.md)), storage volumes and pools, SMART disk health from a JSON report, weekly AI usage from a JSON document.
- **Integrations:** Radarr, Sonarr, Lidarr, Prowlarr, qBittorrent, Jellyfin and Vikunja, read-only (`GET`).
- **Alerts** with a grace period, an event log and optional Web Push notifications (no third party account).
- **Extensions:** server routes, collectors and alert rules, plus client pages and activity sections, loaded from a directory ([docs/extensions.md](../extensions.md)).
- **PWA:** installable, offline shell, themes, your own name, accent color and icons (`config/branding/`).

## Security

- Access mode is `limited` unless you choose otherwise. `trusted-network` and `identity-proxy` are explicit opt-ins, documented in [Access modes](../configuration.md#access-modes); the example configuration is `limited`.
- Secrets live only in the backend (environment or files); the YAML schema has no field to write one.
- Data produced for a visitor with full access is never written to the service worker cache or to local storage, and is dropped from memory on a change of identity, a downgrade to limited access, a rejected request or a lost connection ([What the browser keeps](../ARCHITECTURE.md#what-the-browser-keeps)). Offline, shared and limited data stay available; private sections are empty.
- The app has no Docker socket access. Container: non-root, read-only filesystem, no capabilities, `no-new-privileges`.
- The optional Glances container is separate and far more privileged than the app. [docs/glances.md](../glances.md) says what it can do on your host and which settings of the example reduce that (no `pid: host`, narrow host mount, no published port).

## Install

Docker Compose with `ghcr.io/al31si/orbis-homelab:0.1.0` (`linux/amd64` and `linux/arm64`). Follow the [Quick Start](../../README.md#quick-start): the files come from the `v0.1.0` tag and `ORBIS_VERSION` pins the same version.

## Known limitations

- The `arm64` image is built and inspected but not executed by the project's tests.
- During `0.x` the configuration format and the extension API can change in a minor version. The extension API is version 1.
- Extensions run in the backend process with its privileges and are not limited to `GET` requests (the extension SDK can also send `POST`): install only code you trust.
- Glances (and therefore the System, container and filesystem views) needs a privileged container you must secure yourself.
- One language per instance (`it` or `en`); no accounts or per-user permissions.

## Names used before this release

The project was developed under the working name Belvedere. Extensions built under that name keep working unchanged: see [Extensions written before the rename](../extensions.md#extensions-written-before-the-rename).
