# Orbis Homelab 0.3.0

Orbis now looks like the front panel of a rack: lamps for state, LED meters for quantities, ruled lists and quiet plates. The pages have been rebuilt around that language, with the same data and configuration as before.

## What is new

- **A front-panel design language** ([docs/design-language.md](../design-language.md)). Graphite and mineral-grey themes, small corners, flat surfaces, squared tags and recessed controls. Instrument Sans is bundled with the app; fonts are never fetched from another server.
- **Every main page redesigned.** Home has a state sentence and a service lamp matrix; Services uses ruled lists; System has LED meters; Storage has a drive-bay view; Activity has a timeline. Settings and Diagnostics follow the same language, in Italian and English. Integrations that are not set up show an empty bay with the steps to get started.
- **Navigation stays in the app frame.** The content scrolls inside the shell and the bottom navigation has its own row, fixing the floating bar on mobile browsers and installed apps. A navigation rail or sidebar takes its place on wider screens.
- **A more compact Home on phones.** The Home state plate is compact on phones and the bottom bar has been restyled.
- **Real service logos**, bundled locally for 48 products and available offline ([docs/brand-logos.md](../brand-logos.md)). Exact product names, IDs or integration types select a logo; ambiguous names get a neutral monogram. An explicit `icon:` key selects a product and your own image still takes precedence. Bundled logos are static.
- **Review fixes.** Service detail no longer requests system data when the System feature is off. Storage health shows an unverified state when SMART data cannot be read, rather than claiming clean counters. The header has an opaque background, with separator and contrast fixes across the pages.
- Smaller: app icons, splash images and browser theme colours follow the new palette; logos are served as separate files; the release documentation clarifies that GitHub stores the example environment file as `default.env.example` among the release assets.

## Upgrading from 0.2.0

The configuration format and the extension API are unchanged from 0.2.0. No migration is required: existing configuration, extensions, push keys and subscriptions work as before. See [From 0.2.0 to 0.3.0](../update.md#from-020-to-030) for the Compose update and rollback steps.

## Things that behave differently

- Service icons now use exact product matching and a neutral monogram fallback. Custom icon files still win; use an explicit product key such as `icon: radarr` when a service has a custom name.
- Pages scroll inside the app frame. Lamps and LED meters replace the old health ring and many per-item cards; they keep text equivalents for state and quantity.
- Unreadable SMART data is shown as unverified, and services without the System feature no longer show a memory-share meter.

## Known limitations

- The `arm64` image is built and inspected but not executed by the project's tests.
- During `0.x` the configuration format and the extension API can change in a minor version; neither changes in this release.
- Extensions run in the backend process with its privileges: install only code you trust.
- One language per instance (`it` or `en`).
