# Orbis Homelab 0.2.0

Installing Orbis as an app no longer starts with "you need HTTPS". The Installation page now looks at your browser and at the address you opened it from, and says what is really possible there.

## What is new

- **Installation page rewritten.** It identifies the browser (Chrome, Edge, Brave, Safari, Firefox, Android, iPhone/iPad, in-app browsers) and tells you whether the steps give a full app, an app window, a shortcut or nothing, with the exact menu entries. No "Install" button is shown unless the browser offers one.
- **Plain HTTP on your LAN works as before.** The dashboard needs nothing else; Chrome, Edge and Brave on a computer can open it as an app window from their menu. Offline use and notifications need HTTPS and the page says so, without pretending.
- **HTTPS: the full app.** Over HTTPS (or `localhost`) you get the Install button, the offline shell and notifications; Settings shows whether the service worker is active, and reports a worker the browser refused (usually an untrusted certificate).
- **A guide to HTTPS** ([docs/https.md](../https.md)): Tailscale Serve, a reverse proxy you already run, Caddy with a domain, a local certificate authority, or `localhost` over an SSH tunnel. Settings links each route to its section. Orbis ships no TLS stack and never asks you to disable a browser check.
- **Notifications are described consistently.** The Installation page and the Notifications section follow the same rules: server off, unsupported browser, plain HTTP, iPhone tab, refused service worker, limited access, permission denied, ready, on.
- **Brave and push.** A troubleshooting entry explains "The browser's push service is unreachable" and Brave's **Use Google services for push messaging** setting, with the privacy trade-off ([docs/troubleshooting.md](../troubleshooting.md#the-browser-push-service-is-unreachable)). Settings links to it.
- **`publicUrl` is optional** and only an `https://` address is offered (see below).
- Smaller: the Home install card appears only when there is something to do; the Favorites section is translated; Diagnostics shows a refused service worker; the release now includes `.env.example`.

## Upgrading from 0.1.0

No configuration change is required: see [From 0.1.0 to 0.2.0](../update.md#from-010-to-020).

## Things that behave differently

- `publicUrl: http://...` is accepted but no longer offered anywhere (it cannot give a secure context); the server logs a line at startup.
- `scripts/test-clean-install.sh` refuses to run on a host that already has a Compose project named `orbis-homelab`.

## Known limitations

- Tested on real devices: Brave on Windows (HTTP and HTTPS installation, notifications) and Safari on iPhone (Home Screen installation, notifications). Menu entries for Chrome, Edge, Android, Firefox and Safari on Mac come from the vendors' documentation and the browsers' own menu strings, not from tests on those devices; menu names change with language and version.
- Brave only receives Web Push if **Use Google services for push messaging** is on; that is the browser's choice and a privacy trade-off.
- The `arm64` image is built and inspected but not executed by the project's tests.
- During `0.x` the configuration format and the extension API can change in a minor version.
- Extensions run in the backend process with its privileges: install only code you trust.
- One language per instance (`it` or `en`).
